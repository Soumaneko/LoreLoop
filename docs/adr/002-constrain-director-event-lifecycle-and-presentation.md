# 2. 收敛 Director Event 的生命周期与叙事出口

**Date**: 2026-08-28  
**Status**: Accepted

## Context (上下文与背景)

Director Event 用于表示能够在多回合中自主发展的世界事件。早期设计允许生成端继续创建新事件，同时通过独立的 `foreshadow_setting` 技能投放设定伏笔。这导致了三个问题：

1. 多个活跃事件争夺有限的叙事篇幅，容易产生同质钩子和无法收束的后台线索。
2. 宏观导演决策与事件实例化都在处理 Setting 细节，但缺少对“实际使用了哪些 Fact”的可追溯边界。
3. 静态设定伏笔与 Event Hook 承担了重叠的玩家可见呈现职责，隐藏 Fact 也可能被过早暴露。

## Decision (架构决策)

1. **新生产流程只允许一个活跃事件**：存在 `hidden` 或 `engaged` Event 时不再提供事件创建能力，单批最多创建一个 Event。旧存档中已有的多个活跃 Event 不做破坏性迁移，而是通过正常生命周期逐步排空。
2. **分离宏观选择与事件实例化**：导演决策层使用 Setting 的简要概览选择方向；Event Selector 才获得被选 Setting 的可用 Facts。可用 Fact 具有稳定 ID，Event 持久化它实际采用的 Fact ID，以便去重和追溯。
3. **Hook 是 Event 唯一的玩家可见调度出口**：移除 `foreshadow_setting`。公开 Fact 可直接构成 Hook；隐藏 Fact 可驱动后台因果，但 Hook 只能呈现其可观察后果或痕迹。
4. **事件可在 deadline 前结案**：Reviewer 根据核心冲突的事实状态决定继续或结案。主体被击败或控制、手段永久失效、意图已实现或已客观不可能，均属于终态；暂时受挫不是终态。确认阶段先完成评审，已结案的 Event 可在同一回合重新释放创建名额。

## Consequences (后果与权衡)

### 积极影响

- 叙事资源集中于一个可跟进、可结案的世界冲突。
- Setting Fact 的选用可追溯，同一 Fact 不会被无意反复实例化。
- Event 的后台因果与玩家可见信息具有单一、可审计的边界。
- 事实上已结束的事件不会为等待 deadline 而占用后续叙事空间。

### 代价与限制

- 系统不再并行培养多条独立的活跃 Event 线；世界的其他动态需通过 NPC、Setting 或普通叙事细节表现。
- Fact ID 只能证明事件的设定来源，不能作为“该事件已在正文发生”的历史证据。
- 结案判断仍是概率性语义判断，需要明确终态标准和回归评测。
