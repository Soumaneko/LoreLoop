# 意图分析规则

在输出结构化行动前，必须先在 analysis 字段中用 3-6 句中文进行简短、可见的意图分析摘要。必须依次覆盖：

1. 用户的直接意图：用户字面上想做什么。
2. 隐含暗示与风格：用户描述中隐藏的真实目的和动作风格（如暴力、谨慎、欺骗）。
3. 可行性判断：基于 CurrentState 的位置、NPC、物品和状态，该意图是否具备物理或逻辑上的可执行性。
4. 合规检查：是否违反 CoreMemory 的世界规则或角色能力边界。若违反，说明将如何合理降级或约束该行动。
5. 行动定调：综合以上，明确说明应将此输入解析为几个 action。严禁将“计划”作为最终解读，一切计划必须转化为当前的实际第一步。


# 行动抽取与拆分规则

## 基础规则
- 必须至少抽取一个行动
- 用户输入中的内心思考或"想要做XX"，并不单纯表达"想要"，这是它选择的行动。
- 当用户描述了一个需求并暗示了解决方案时，行动应解析为实现方案的具体下一步，而非"思考如何实现"。"思考"不是行动。
- ActionType 严禁是 计划/思考/等待/考虑 等。
- 行动需要符合逻辑，以及 CoreMemory 中的核心设定。
- **禁止替换用户明确指名的目标角色**。用户知道自己在说谁。严禁自动归并到在场 NPC。应保留原始 target 名，并将"需要移动到该角色所在位置"作为前置行动提出。

## 拆分粒度与风味保留
- 最小化拆分：不要把同一意图下的连续姿态、伪装细节、移动方式拆成多个 action。只有当动作目标、判定方式或后续用途不同时才拆分。
- 最大化保留细节：如果用户用了生动的语言（如“猛踹大门”、“附耳低语”、“反握匕首”），严禁只提取简单的动词。必须将这些情境和姿态细节完整保留并填入 method（方法）和 goal（目的）字段中，为下游的情节与场景生成提供丰富素材。
- 行动者：actor 字段应使用 CurrentState 中的玩家姓名，不要使用“主角”或“我”。

## ActionType 定义

- move: 移动、接近、绕行、撤退
- observe: 观察、侦查、倾听、检查环境
- inspect_object: 检查物品、门锁、痕迹、机关
- interact_object: 使用、拿取、交出、打开、破坏物品
- speak: 对话、询问、说服、威胁、撒谎
- signal_ally: 暗号、手势、眼神、提醒同伴
- instruct_ally: 指挥、安排、请求同伴行动
- hide_or_stealth: 潜行、隐藏、伪装、避开视线
- attack: 攻击
- defend: 防御、保护、格挡
- cast_or_use_power: 施法、异能、特殊能力
- wait: 等待、拖延、观察时机
- other: 无法归类的其他行动

## likely_needs_roll 规则

- True：与世界互动且遭遇不确定性或抵抗时（包括但不限于：潜行、说服、欺骗、威胁、开锁、攻击、防御、施法、危险地带移动）。如果你不确定，倾向于 True。
- False：简单且无障碍的移动、日常交谈、明确交付已有物品、无需技巧的观察。

## risk_level 规则

必须是 low、medium 或 high 之一。判断不应仅看动作本身，必须结合上下文：
- low：安全环境、友善/中立目标、无欺骗/威胁、失败只会浪费时间而无实质性惩罚。
- medium：具备一定不确定性、涉及说服/轻度试探、对抗性对话、失败会导致一定成本或尴尬。
- high：目标实力远超玩家或具有攻击性、涉及战斗、严重欺骗、威胁、极度危险的施法、失败可能导致受伤、暴露或关系彻底破裂。

判断需要考虑的角度：
1. 目标的实力与态度，例如对龙说话不同于对朋友说话。
2. 场景氛围与位置，例如私密对峙不同于公共宴会厅。
3. 行动类型，attack、hide_or_stealth、cast_or_use_power、defend 的基准偏高。
4. 最近剧情摘要中的事件，例如刚逃离生命危险不同于刚完成普通对话。
5. CoreMemory 中的世界反馈规则。

如果信息不足，使用 action_type 和当前场景做保守估计；不要为了制造戏剧性而夸大风险。
