## 核心更新原则

- 绝对忠于原文：只更新受剧情原文明确影响的字段。未受影响的字段必须保持原值。
- 禁止过度推断：不要根据剧情“推测”未发生的变化。例如角色说“我打算去某地”但尚未行动，不得改变位置；未明确说明丢弃或消耗物品，不得扣除库存。

## 详细更新规则

1. Scene 与 Player
   - location & position：如果剧情描写了实际的移动并到达或经过某处，即使角色尚未抵达最终目的地，也必须将 scene.location 和 player.position 更新为剧情结束时角色实际所在的位置。不要保留已过时的旧位置描述。
   - atmosphere：只用简短词汇概括当前场景氛围（如"紧张"、"温暖嘈杂"、"肃杀压抑"），不要写成描写性长句。
   - player condition：如果有明确的身体/精神状态改变，更新该列表。如果不再处于某种状态（如不再受伤），直接从列表中移除该项，不要添加“不再受伤”这种冗余条目。
2. NPCs 与 Mentioned NPCs
   - 新增 NPC：在剧情中出现且有交互意义的角色，加入 npcs 列表。不确定的字段保持 null。
   - 移除 NPC（严格限制）：只有当 NPC 在剧情中明确离开、告别、消失、被遣散，或场景地点发生变更且该 NPC 没有明确跟随时，才将其从 npcs 中移除。对于仅在当前场景中未被提及的 NPC，保留其在列表中（系统会自行处理隐性缺席）。
   - NPC 标识：npcs 列表中的每个 NPC 必须只用 name 字段来识别，绝对不要修改已有 NPC 的 name。
   - mentioned_npcs：列出本回合剧情原文中被提及或涉及的所有 NPC 名字列表，包括对话、被观察、行动、被点名，甚至是在内心独白或背景联想中一笔带过的 NPC（该字段用于系统底层的出场频率计算）。
3. World Clock
   - 一天有 6 个 phase，phase_index 映射固定如下：0 = 凌晨, 1 = 上午, 2 = 下午, 3 = 黄昏, 4 = 晚上, 5 = 深夜
   - 返回剧情结束后的最终 day 和 phase_index。不要返回自然语言时间，不要返回推进了几个 phase。
   - 如果剧情没有明确时间流逝，或只是几分钟内的动作，保持当前 day 和当前 phase_index。
   - 如果剧情明确进入新的时间段，直接输出剧情结束时的最终时间。例如当前是第1日深夜，剧情写"破晓前出发，走到正午"，则输出 day=2、phase_index=2。
   - 时间单向性与自检：CurrentState 永远表示当前实际时间，不表示回忆时间。输出前务必自检：day 和 phase_index 组合的绝对时间绝不能早于当前状态。如果剧情描述了过夜（清晨醒来、第二天、次日等），day 必须比当前更大。
4. Resources (Inventory & Money)
   - inventory 列表中的每项格式为 "name": "物品名", "quantity": 数量，quantity 必须是正整数。
   - 物品获得：
      - 必须有明确的获得动作（收到、拾取、购买、缴获、制作等）才添加物品。
      - 剧情明确数量时使用明确数量；不明确时默认增加 1（复数描述默认加 2）。
      - 禁止：剧情仅仅提及、展示、佩戴或使用某物时（如“你用钥匙开门”），不得作为新物品添加。
   - 物品消耗/失去（逐项检查）：
      - 消耗性使用（如喝药水、射箭）或明确失去时，减少 quantity；非消耗性使用（如用钥匙开门）保持数量。
      - 数量减至 0 或更少时，从 inventory 中彻底移除该对象。
   - 金钱变化：
      - 默认 money_unit 为“金币”。明确获得/花费时更新 money。
      - 模糊花费处理：如果明确发生消费但未说明金额，且当前 money 足够，必须扣除合理小额（通常 1-3，较大购买扣 5）。不要因为金额不明就忽略花费记录。如果当前 money 是 null，保持 null。
