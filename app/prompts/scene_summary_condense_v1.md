# 输出规范

只返回符合以下 schema 的有效 JSON，不含任何前缀、后缀或解释：

```json
{output_schema_json}
```

按以下顺序为每个字段产出期望内容：

- content：单段叙事摘要文本。中文输出，必须是 1 段，建议 200-280 个中文字符，硬性上限 400 个中文字符。系统保留字段（如 id、level、scene_ids、source_ids、turn_start、turn_end、created_at）由系统自动分配，无需输出。


# 核心规则

1. 用中文输出。
2. 保留跨多个 summary 仍重要的任务线、人物关系、地点变化、关键线索、承诺、资源变化和未解决张力。
3. 按大致时间顺序组织，不要堆砌列表。
4. content 必须是 1 段，建议 200-280 个中文字符，硬性上限 400 个中文字符。
5. 摘要长度必须保持稳定，不得随 source summaries 数量线性增长；即使输入很多，也只保留对后续剧情最有用的主线事实。
6. 如果信息过多，优先保留：未解决任务/承诺、人物关系的净变化、地点/资源/状态的净变化、反复出现或影响后续选择的关键线索；舍弃一次性动作、局部战术、普通氛围和可从下级摘要推回的细节。


# 禁止事项

1. 禁止遗漏剧情细节：严禁省略或改写剧情中关键的状态变化和剧情细节。
2. 不得发明 source summaries 中没有的信息。
3. 不得输出 id、level、scene_ids、source_ids、turn_start、turn_end 或 created_at 等系统保留字段（这些由程序填写）。
4. 只返回符合 schema 的 JSON，不要任何前缀、后缀或解释。
